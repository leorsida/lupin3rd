# SEO and GEO

GEO here means **Generative Engine Optimization**: being found, read and cited
correctly by generative engines. It does not mean local or geographic SEO. The
desk is distributed and the servers are in Iceland; there is no place to
optimise for.

All of this lives in the theme. The prototype allows one lightweight plugin for
"meta and sitemap only", but a theme that already owns its markup can own its
metadata too, with fewer moving parts and no settings screen to get wrong.

## Technical SEO — `Seo`

- `add_theme_support( 'title-tag' )` plus a `document_title_parts` filter.
- Meta description from the standfirst or the kicker. Never auto-generated
  filler, never the first 160 characters of the body.
- Canonical URL on every view; `noindex` on search results and on author
  archives.
- Open Graph and Twitter Card. The image is the **generative mark rendered
  server-side to PNG and cached** — see `Marks` — because Open Graph needs a
  real file and the site has no photographs.
- Native WordPress XML sitemap, with authors and private post types excluded.
- Reciprocal `hreflang` pairs. Prepared in phase 1, active in phase 2.
- One `h1` per page, headings in order, a real breadcrumb.

## Structured data — `Schema`

| Context | Types |
|---|---|
| Site-wide | `Organization`, `WebSite` with `SearchAction` |
| News | `NewsArticle` |
| Tutorial | `TechArticle` + `HowTo` with `totalTime`, `supply`, `step` built from the `h2` headings |
| Dossier | `Article` + `isPartOf` |
| Everywhere | `BreadcrumbList` |
| Authors | `Person` with `sameAs` for the PGP key and Matrix handle |

`Person` never carries an email address or a last-seen timestamp.

## Generative surface — `Geo`

- `/llms.txt` and `/llms-full.txt`, generated by the theme: what the magazine
  is, the licences (CC BY-SA 4.0 for text, MIT for code), how to cite it, an
  index of the sections.
- A **citable summary** at the top of every article: two or three sentences
  that stand on their own out of context. This is also just good journalism.
- The "in short" / "final check" box is a structured block, not loose prose.
- Explicit `datePublished` and `dateModified`, and corrections kept at the foot
  of the piece. Both are what make an article safe to cite.
- Stable slugs. Old URLs keep working; nothing is ever silently redirected.
- `robots.txt` states explicitly which generative crawlers are allowed, and
  `llms.txt` says *why*. The policy is set by D-016 and follows from the
  licence: crawlers that fetch in order to answer and cite are allowed
  (`OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`, `ChatGPT-User`,
  `Claude-User`); collectors that build training corpora are not (`GPTBot`,
  `ClaudeBot`, `meta-externalagent`, `CCBot`, `Google-Extended`), because
  CC BY-SA's share-alike condition cannot be honoured by model weights.
  Two things to keep in mind: `robots.txt` is a request rather than a control,
  and the token list goes stale — review it quarterly and record the date.

## Trap to avoid

The archive filters in the prototype hide posts client-side. A crawler sees
every post regardless of the active filter, and a reader without JavaScript
sees no filtering at all. Filters must therefore have real URL variants that
run a server query, with the client-side filter acting only as an accelerator.
The same applies to the search overlay.
